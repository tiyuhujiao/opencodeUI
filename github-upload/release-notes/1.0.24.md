# opencode-ui 1.0.24

本版本把 `1.0.22` 之后累积的改动一次性发布，重点是 OpenCode v2 原生表单、OAuth 生命周期、运行隔离，以及 agent 列表与 CLI 完全对齐。

## Agent 列表与 CLI 对齐

- 修复「扩展里只有 Build、看不到 Plan」：OpenCode v2 仍保留 Build / Plan 两个内置 primary agent，问题是按目录惰性初始化的实例在冷启动后第一次 `/api/agent` 返回空列表。现在 v2 请求在列表为空时按 `150/300/600/1200ms` 重试，直到拿到非空结果；空响应也不再覆盖界面已有列表。
- 移除前端硬编码的可见/隐藏 agent 名单，统一按服务端返回的 `isPrimary` / `hidden` 过滤，并透传 `displayName` 与 `description`。CLI 里能看到的 agent（含之后安装 omo 等预设加入的自定义 agent）会原样出现在侧边栏下拉中。
- 默认 agent 仍优先 `build`，选中的 agent 若临时不在列表里也会保留在选项中，避免被静默切走。

## OpenCode v2 原生表单与阻塞请求

- 新增共享原生表单模型与 `V2FormFields` / `V2QuestionBanner`，贯通 API、实时事件、协议、运行快照与 Provider 登录界面；保留 boolean/number/integer/multiselect 类型，按原生顺序应用默认值、AND 条件与多选包含判断。
- 多个待处理表单/权限请求会全部保留并逐个展示，blocker 轮询串行化；外部完成或答复后同步快照，避免已回答的表单再次弹出。跨会话的权限与问题请求不再串入当前运行。

## OAuth 与 Provider

- 登录流程绑定原始 endpoint、工作目录、Provider、method 与原生 `attemptID`，按服务端 `time.expires` 等待；轮询、complete 与等待都支持取消，关闭时仍接收迟到的 admission ID 并立即清理。
- Provider 设置同时支持旧版 `provider/{npm,options}` 与原生 `providers/{package,settings}`，保留 JSONC 注释与未知字段，API key 与敏感请求头继续屏蔽。

## 稳定性

- 修复 serve 探测/启动与销毁、受管子进程退出之间的竞态：跨 await 固定 runtime、端口与目录并校验生命周期代次，销毁时等待在途操作。
- 统一 SSE 断流与「连接仍在但没有事件」的恢复路径，事件流建立增加 10 秒期限；按发送前的历史 ID 基线识别本轮 `idle` 的 `succeeded/failed/interrupted`，成功终态缺少 `finish` 时也能正确收尾。
- 排队中的斜杠命令改由服务端生成的消息 ID 认领；不可回答的表单自动取消；错误正文改为可读信息；重试步骤不再重复渲染。

# opencode-ui 1.0.24

This release ships everything accumulated since `1.0.22`. The headline changes are native v2 forms, OAuth lifecycle hardening, run isolation, and an agent list that matches the CLI exactly.

## Agent list parity with the CLI

- Fixes "only Build is visible, Plan is missing": OpenCode v2 still ships Build and Plan as built-in primary agents. The real cause was the lazily initialised per-location runtime returning an empty `/api/agent` list on the first call after a cold start. v2 requests now retry (`150/300/600/1200ms`) until the list is non-empty, and an empty response no longer overwrites the agents already shown.
- The webview no longer keeps hardcoded visible/hidden agent name sets. Agents are filtered by the server-provided `isPrimary` / `hidden` flags, and `displayName` / `description` are passed through, so every agent the CLI lists appears in the sidebar picker — including custom presets installed later by projects such as omo.
- The default agent still prefers `build`, and a selected agent that temporarily disappears from the list stays selectable instead of being silently switched.

## Native v2 forms and blockers

- A shared native form model plus `V2FormFields` / `V2QuestionBanner` spans the API, live events, protocol, run snapshot, and provider sign-in UI, preserving boolean/number/integer/multiselect types, defaults, AND conditions, and multiselect containment in native order.
- Multiple pending forms and permission requests are all kept and shown one by one with serialized blocker polling; externally completed requests resync the snapshot so answered forms do not reappear. Cross-session permission and question requests no longer leak into the current run.

## OAuth and providers

- Sign-in flows bind the original endpoint, working directory, provider, method, and native `attemptID`, waiting on the server-provided `time.expires`. Polling, completion, and waiting are cancellable, and late admission IDs are still accepted and cleaned up on close.
- Provider settings accept both the legacy `provider/{npm,options}` shape and the native `providers/{package,settings}` shape, preserving JSONC comments and unknown fields while masking API keys and sensitive headers.

## Stability

- Race conditions across serve probing/startup, disposal, and managed child process exit are fixed: runtime, port, and directory are pinned across awaits with lifecycle generation checks, and in-flight work is awaited on dispose.
- SSE drops and "connected but silent" streams share one recovery path, with a 10 second deadline for stream establishment. Idle results are classified from the pre-send history ID baseline, and a successful terminal state without `finish` now closes the run correctly.
- Queued slash commands adopt the server-generated message ID, unanswerable forms cancel themselves, error bodies render as readable text, and retried steps no longer duplicate output.
